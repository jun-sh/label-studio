## 10. 故障排查要点

### session.FAILED / G6 IMU_ALIGN_NULL

- **fix2 前：** 半 NaN sensor_raw 行 → 对齐 null 超 1%  
- **fix2 后：** 应 G6 0%；若仍失败：查 `sensor_raw/imu` both_ok 占比、主表 jsonl `observation.imu_*`  
- 确认镜像 tag 为 **fix2**，容器内 `PAIR_TOLERANCE_NS=3_000_000`

### session.FAILED / GATE_INTERNAL_ERROR

- 主表 jsonl 含非法 `NaN` 字面量 → fix1 已 sanitize；查 derive 日志

### session.FAILED / IMU_RAW_MISSING (G5)

- `sensor_raw/imu/chunk-000/file-000.parquet` 缺失或空 → 查 raw tar 内 `imu_raw.jsonl`

### session.FAILED / PARQUET_INDEX_GAP (G1)

- frame-map 不连续 → 多 session/segment 状态未齐；查 `meta/episodes/episode_000.json`

### derive 锁未释放

- `state/deriver.lock` 残留 → fix1 `releaseDeriverLock`；手动：`docker stop data-lab-derive-worker-1 && rm state/deriver.lock`

### reset 后 derive 缺 info.json / G4 SCHEMA_INVALID

- reset 清空 `meta/`；正常 **130 上传路径** 会 bootstrap schema  
- 仅从 raw 重 derive 时需预先写入 `meta/info.json`（含 `codebase_version`、video features）— 生产以上传路径为准

### upload 后无 derive

- `DERIVE_ASYNC=0`：需 `ego-derive run` 或 derive-worker watch  
- 查 `session.DONE_UPLOAD`、segment `DERIVE_PENDING`

### ego-run-pipeline 卡住

- 合并 episode 场景：见 Task-P-1  
- 内参缺失：部署 `camera_intrinsics.json`  
- 日志：`derive 进行中，待 parquet: sess_xxx`

## 14. 架构评估（fix2 vs Foxglove 工业范式）

**评估日期：** 2026-08-20  
**结论：** fix2 **未严重偏离** Foxglove Data Platform 核心范式；存在若干**落地期取舍**与**规模化瓶颈**，需在 P1/P2 收敛，不阻塞 P0 灰度。

### 14.1 Foxglove 工业范式基线（本项目采纳子集）

| 原则 | 含义 |
|------|------|
| **原始归档不可变** | `raw/segments/*.tar.zst` 为唯一可信源，派生层可 wipe 重建 |
| **Segment → Session → Episode 三层** | 最小单元、采集会话、训练样本语义分离 |
| **显式状态机 + 磁盘 marker** | `DONE_UPLOAD` / `DERIVING` / `READY` / `FAILED` 可观测、可重跑 |
| **派生与采集解耦** | `DERIVE_STANDALONE=1`：上传写 marker，derive 独立进程/CLI 触发 |
| **幂等重放** | 同 raw 可重复 derive；`--force` 重传双向同步 segment 状态 |
| **流式 ingest 理想态** | 录制过程中或段关闭后**增量**进入平台，worker **按 recording 认领**派生 |

> 权威设计基准：[ego-001-phase0-design-freeze.md](./ego-001-phase0-design-freeze.md)

### 14.2 fix2 完整保留的范式模块

| 模块 | 路径/脚本 | 说明 |
|------|-----------|------|
| 三层实体 + frame_segments | `derive/frame-map.mjs` | 全局帧映射，废弃 frameBase |
| Segment 状态机 | `ingest/segment-state.mjs` | RECEIVED → DERIVE_PENDING |
| Session marker | `session-markers.mjs` | READY 门禁 6/6 |
| Derive 流水线 | `derive/pipeline.mjs` | Phase0 §6 步骤 1–10 |
| READY 门禁 | `derive/ready-gate.mjs` | G1–G6 可执行校验 |
| 生命周期 GC | `derive/lifecycle-gc.mjs` | READY 后 staging 清理 |
| Raw 保留 reset | `ego-reset-34-only.sh` | 仅清派生，保留 raw |
| 运维 CLI | `ego-derive` / `ego-deliver` | 签名不变 |

### 14.3 合理业务定制（不构成偏离）

| 定制 | 理由 |
|------|------|
| LeRobot v3 parquet/jsonl/mp4 布局 | 训练侧消费契约 |
| OAK 四路 JPEG（`OAK_H264=0`） | 硬件与 mux 路径 |
| `sensor_raw/imu` 200Hz + 主表 30Hz 对齐 | IMU 双存储 + G6 门禁 |
| Viewer stream API + embed | 可视化交付 |
| `STREAM_SESSION_SINGLE_EPISODE=0`（灰度锁定） | 每趟录制 = 独立训练样本 |
| fix2 IMU 3ms 配对容差 | 硬件 accel/gyro 时差统计适配 |

### 14.4 真实架构偏离点与风险

| 偏离点 | 现状 | 风险 | 优先级 |
|--------|------|------|--------|
| **批式 tar.zst 上传** | 130 录完 → 打包 → 一次 HTTP 上传 | 非 Foxglove 理想「录制中增量 ingest」；首帧可见延迟高 | P2 |
| **全局 frame_map 累积 derive** | 每次 derive 遍历**全部** `frame_segments`（P0 实测 7 session → derive 99s） | 随历史 session **线性变慢**；与「单 session 独立样本」语义冲突 | **P1** |
| **单站 `deriver.lock` 串行** | 同 station 同时仅一个 derive | 多采集员/多 session 排队；非分布式 worker | P1 |
| **derive 与 ingest 同容器** | `stream-ingest` 内联 Node derive | 34 横向扩容需拆 worker 池 | P2 |
| **Collection UI / derive-status** | 仍读 legacy markers API | 运维误判（Task-P-1）；**不以网页为准** | P1 |
| **无结构化耗时指标** | 仅 event 日志 + ingest `elapsedMs` | 性能回归难以及早发现 | P1 |

### 14.5 幂等重试：fix2 vs Foxglove 原生模型

| 维度 | Foxglove 原生（理想） | fix2 实现 |
|------|----------------------|-----------|
| 可信源 | Recording blob / MCAP | `raw/segments/*.tar.zst`（不可删） |
| Ingest 重试 | Worker 按 recording_id 幂等写入 | tar 校验失败 → `INGEST_FAILED`；`ego-derive run` 重试 |
| Derive 重试 | Job queue claim + at-least-once | `deriver.lock` + 手动/derive-worker；mux `DERIVE_MUX_AUTO_RETRY` |
| 上传重试 | 分片续传 | 130 `UPLOAD_FAILED` → 手动 `--force` |
| 全量重建 | 从 recording 重放 | `ego-reset-34-only` + `ego-bootstrap-raw-sessions.sh` + derive |

**结论：** 幂等语义**对齐范式**（raw 不可变、可重 derive）；**差异**在批式上传与单进程串行，非「数据不可重放」类偏离。

### 14.6 多机采集 / 多 34 扩容瓶颈

| 瓶颈 | 说明 |
|------|------|
| **单 `STREAM_DATA_ROOT` 绑定** | 每 34 节点独立 stream 目录；多 34 需 station 路由或共享存储 |
| **`deriver.lock` per station** | 无法同站并行 derive；多 130 → 单 34 形成队列 |
| **frame_map 全局单文件** | `episode_000.json` 单点；多 episode 需 schema 演进 |
| **nginx + stream-ingest 单点** | 无 ingest 水平分片 |
| **130 手动 upload** | 边缘无自动 failover 到备用 34 |

### 14.7 长期架构收敛建议（P2+，新分支）

1. **增量 derive**：`--session` 仅处理该 session 的 segment，不重建全量 frame_map 历史（Task-P-1 联动）。
2. **derive-worker 池**：独立容器 + 按 session 分片锁，替代全局 `deriver.lock`。
3. **130 流式 segment 上传**：段关闭即传（仍 tar.zst 或 chunked），缩短「录完才可见」窗口。
4. **结构化 metrics**：derive 各阶段 `elapsed_ms` 写入 `live/derive/profile.json`。
5. **Collection API**：对齐 `session.READY` marker（Task-P-1）。

## 15. 性能基线与耗时分析

### 15.1 分层对比：本地直采派生 vs 跨节点完整链路

| 阶段 | 本地直派生（34 only） | 完整链路 130→34（P0 实测） | 额外开销 |
|------|----------------------|---------------------------|----------|
| 采集 | — | ~20s（含 12s API 冷却） | +20s |
| 130 tar 打包 | — | ~1–3s（含于 upload） | +1–3s |
| 网络上传 | — | ~1–2s（~246 帧 tar ~数十 MB，内网） | +1–2s |
| 34 tar ingest | — | ~2–5s（`tarzst_segment_ok.elapsedMs`） | +2–5s |
| ingest 轮询等待 | — | 0–180s（`rc-e2e-upload.sh` 无进度条；**非 ingest 本身**） | 运维感知延迟 |
| derive | **~23s**（单 session ~304 帧，stability 5 轮） | **~50–99s**（随历史 session 累积） | +27–76s |
| preflight | — | ~2s | +2s |
| **合计** | **~23s** | **~276–301s/趟**（4.6–5.0 min） | **~12×** |

**P0 真机实测（`.p0-gray-trial-log.jsonl`）：**

| 趟次 | 总耗时 | READY 帧数 | G6 null |
|------|--------|-----------|---------|
| 1 | 276s | 1099* | 0% |
| 2 | 288s | 1344* | 0% |
| 3 | 301s | 1590* | 0% |
| 4 | — | 1835* | 0% |

\*帧数为 **累积 frame_map 总行数**，非单趟独立样本行数（见 §15.4）。

### 15.2 瓶颈归因

| 类型 | 占比（经验） | 定位方式 |
|------|-------------|----------|
| **derive 全量重放** | **40–60%** 且递增 | `rc-ego-001-pipeline-profile.sh` 看 `frame_segments` 数量 |
| 采集 + 冷却 | ~7% | 130 API `/api/capture` |
| 网络 + tar 传输 | ~5% | upload `elapsed_s` |
| tar 解压 + ingest | ~5% | `tarzst_segment_ok.elapsedMs` |
| MP4 mux（四路） | ~15–25% | derive 日志 `derive_mux_done` |
| IMU 对齐 + parquet | ~10–15% | `derive_main_table_done` |
| 轮询/串行锁等待 | 可变 | `deriver.lock`、ingest poll |

### 15.3 串行 derive：落地取舍 vs 架构偏离

| 判断 | 说明 |
|------|------|
| **P0 落地取舍** | `DERIVE_ASYNC=0` + 手动 `ego-derive run` + `derive-worker` 停止 → **刻意**隔离问题、避免队列混淆 |
| **架构偏离（P1 需收敛）** | 全局 `deriver.lock` + 全量 segment 重 derive → 不符合 Foxglove「按 recording 增量派生」 |
| **非性能 bug** | 单 session 首次 derive ~50–62s（~246 帧）在基线内 |
| **性能 bug 征象** | 同站第 N 趟 derive 随 N **线性增长**（62s→99s）；历史 session 未隔离 |

### 15.4 正常耗时基线（ego-001，~250 帧/趟）

| 指标 | 合理范围 | 异常信号 |
|------|----------|----------|
| 130 upload | 1–5s | >30s 查网络/磁盘 |
| 34 ingest | 2–10s | >30s 查 tar 大小/zstd |
| derive（**仅当前 session**） | 20–65s | >90s 查累积 derive |
| 全链路 P0 | 4–6 min/趟 | >8 min 查 derive 历史堆积 |
| G6 null | 0%（fix2） | >1% 查 IMU 配对 |

### 15.5 子问题答复

**Q1：fix2 derive 是否支持子步骤打点？**

- **现状：不支持结构化 metrics 导出。**
- 仅有事件日志：`derive_segment_start` → `derive_main_table_done` → `derive_mux_done` → `derive_ready`。
- Ingest 有 `tarzst_segment_ok.elapsedMs`；derive 各阶段**无**统一 `elapsed_ms` 字段。
- **定位脚本：** `scripts/rc-ego-001-pipeline-profile.sh`（解析 marker 时间差 + docker logs）。

**Q2：130 能否取消 tar 打包、改流式 segment 上传？**

- **fix2 / Phase0 冻结：不可以。** 上传协议为 `tar.zst`，130 手动 `upload_segments`（§1.1 不可改动）。
- 34 内部存在 `frame_push` / `handleStreamUpload` 路径（`stream-ingest.mjs`），**未**与 130 生产协议对接。
- 流式对齐 Foxglove 范式属 **P2 新分支**（需 130 + 34 契约变更），本次灰度不落地。

**Q3：derive 成功率指标定义**

| 级别 | 阈值 | 说明 |
|------|------|------|
| **灰度观测（P0/P1）** | **≥95%** | 10 趟中允许 ≤1 趟 FAILED（须可重跑 derive 恢复） |
| **生产长期目标** | **100%** | 连续班次无 FAILED |
| **A 类（零容忍）** | 代码缺陷 | G6 回归、锁泄漏、gate 崩溃、schema 破坏 → 阻断发布/回滚 fix1 |
| **B 类（可重跑）** | 瞬时外部 | 网络闪断、130 磁盘满、mux 偶发失败 → 保留 raw，`ego-derive run` 重试；**raw 不可篡改** |

### 15.6 分层优化方案

**P0 灰度（仅调参/运维，不改 feat 代码）：**

| 动作 | 效果 |
|------|------|
| 严格「一趟 → READY → 下一趟」 | 避免多 DONE_UPLOAD 堆积 |
| 保持 `derive-worker` 停止 + 手动 derive | 状态可观测 |
| 用 `rc-ego-001-pipeline-profile.sh` 每趟打点 | 发现 derive 恶化趋势 |
| 单 session 完成后记录**本趟 raw 帧数**，勿以 marker.total 作单样本行数 | 避免误判 |
| 必要时 periodic `ego-reset-34-only` + 仅保留当前 raw（**慎用**） | 控制 derive 历史（仅测试环境） |

**P1（新分支）：**

- 增量 derive（仅新 session segment）
- 开启 derive-worker + `DERIVE_ASYNC=1`（成功率 ≥95% 后）
- Collection derive-status 适配 `session.READY`（Task-P-1）
- derive 子阶段 `elapsed_ms` 持久化

**P2（新分支）：**

- 130 段级流式上传 / 多 34 路由
- derive-worker 水平池 + 分片锁
- OpenTelemetry / 指标面板
