## 1. 灰度前置：Episode 定义对齐

### 1.1 两种模式对比

| 配置 | 业务语义 | Parquet / frame-map | 训练侧影响 |
|------|----------|---------------------|------------|
| **`STREAM_SESSION_SINGLE_EPISODE=1`**（当前 fix2 overlay） | 多次启停录制 → **合并进同一 episode**（`episode_index=0`，`frame_segments` 累加） | 主表行数 = 各 session 帧数之和；全局 `frame_index` 连续 | 一次上传多趟录制 = **一个长 episode**；需训练管线按合并 episode 消费 |
| **`STREAM_SESSION_SINGLE_EPISODE=0`** | 每次启停 = **独立 episode / 独立数据集世代** | 每 session 独立 derive 产物（或覆盖策略需另行约定） | 与「一趟录制 = 一条训练样本」更一致 |

### 1.2 灰度决策（已执行）

**业务确认：每趟录制 = 独立训练样本 → `STREAM_SESSION_SINGLE_EPISODE=0`**

已在 `docker-compose.v0.0.13-fix2.yml` 生效；recreate 后 `ego-reset-34-only` + `ego-bootstrap-raw-sessions.sh` + 手动 `ego-derive run`。

> **重要：** 灰度 SOP 须「一趟 → READY → 下一趟」。若 reset 后一次性 bootstrap 多 session 再 derive，frame-map 仍会合并多趟数据；现场采集必须串行等待 READY。

## 3. 生产主力 SOP（灰度期间强制执行）

```
┌─────────────┐    ┌──────────────┐    ┌─────────────┐    ┌──────────────────┐
│ 130 录制    │ →  │ upload       │ →  │ derive      │ →  │ READY / FAILED   │
│ Start→Stop  │    │ upload_segs  │    │ (自动/手动) │    │ 再开始下一趟录制 │
└─────────────┘    └──────────────┘    └─────────────┘    └──────────────────┘
```

### 3.1 操作步骤

1. **130 录制**：`http://10.10.10.130:8080` Start → 作业 → Stop  
2. **上传**（130）：
   ```bash
   set -a; source ~/.config/ego-station.env; set +a
   export PYTHONPATH=/home/server/workspace/ego-studio/src
   /home/server/workspace/ego-studio/.venv/bin/python -m ego_capture_studio.cli.upload_segments \
     --ensure-session \
     --segment-root /home/server/cache/ego-001/segments \
     --upload-url http://10.10.10.34:8080/lerobot/api/collection/stations/ego-001/upload
   ```
3. **等待 derive 结束**（34）：
   ```bash
   STATION_ID=ego-001 data-lab-platform/scripts/ego-derive status --watch
   # 或检查 marker（§5.1）
   ```
4. **验收**：`session.READY` 存在 → Viewer 可播 → 再开始下一趟  
5. **若 FAILED**：查 `session.FAILED` 内 `reason.code`，修复后 `ego-derive run --session <id>`

### 3.2 禁止事项（灰度期）

- ❌ 不等 READY/FAILED 连续录制 + 上传（导致 raw 积压、UI 误导）
- ❌ 依赖 Collection 页「markers / 等待处理」判断成功
- ❌ 使用 `ego-reset` 误删 `raw/segments`（仅用 `ego-reset-34-only.sh`）
- ❌ 多 session 合并作为日常业务模式（`SINGLE_EPISODE=1` 仅作能力验证）

## 4. Derive 触发策略

fix2 overlay：`DERIVE_ASYNC=0` → **上传后不会自动 derive**。

| 模式 | 配置 | 适用 |
|------|------|------|
| **手动** | `docker stop derive-worker`；上传后 `ego-derive run` | 灰度初期、问题隔离 |
| **自动** | `docker start derive-worker`（watch `DONE_UPLOAD`） | 稳定后推荐 |


### 5.2 G6 IMU null 率快查

```bash
python3 << 'PY'
import json
from pathlib import Path
p = Path("data-storage/stream/ego-001/data/chunk-000/file-000.jsonl")
miss = tot = 0
for line in p.read_text().splitlines():
    if not line.strip(): continue
    r = json.loads(line)
    for k in ("observation.imu_accel", "observation.imu_gyro"):
        tot += 1
        v = r.get(k)
        if v is None or (isinstance(v, list) and any(x is None for x in v)): miss += 1
    if r.get("observation.imu_timestamp") is None: tot += 1; miss += 1
print(f"G6_null={100*miss/max(1,tot):.2f}% rows={tot//3}")
PY
```

## 6. 故障处置速查

| 现象 | 处置 |
|------|------|
| derive 卡住 | 查 `deriver.lock`；`docker stop derive-worker`；删 lock；`ego-derive run` |
| `session.FAILED` G6 | 确认 fix2 镜像；查 `sensor_raw/imu` both_ok |
| Collection「8/8 等待处理」 | 多 raw 积压或 markers API 缺口；以 §5.1 为准；必要时 `ego-reset-34-only` + 清 orphan raw |
| Viewer 空白但 READY 存在 | Task-P-1 UI 问题；用 §5.4 直链 |
| `ego-run-pipeline` 失败 | 查 `camera_intrinsics.json`；查 `data-storage/samples/egodome.zip` |
| 连续录制后数据合并意外 | 检查 `STREAM_SESSION_SINGLE_EPISODE`；与业务对齐 §1 |
