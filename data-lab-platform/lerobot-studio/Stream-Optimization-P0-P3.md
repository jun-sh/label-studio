## 4. 分阶段详细优化内容

### 4.1 P0 核心稳定性修复（解决致命可用性问题）

**目标：** 修复在线状态误判、采集阻塞丢帧、重复 / 覆盖写入三大致命问题

#### 精准在线状态判活

- **采集端：** 启动后每 15s 周期心跳，独立守护线程执行
- **平台端：** 每收到一帧自动刷新心跳时间
- **判活规则：** 45s 内心跳 / 帧活动 → 在线；否则离线

#### 采集上传异步解耦

- 主线程仅负责 OAK 同步采帧，永不阻塞
- 独立上传工作线程消费队列，JPEG 编码 + POST 后台执行
- 队列最大长度 300（≈10s@30fps），满则丢弃最旧帧，保障采集优先

#### 帧幂等 + 断点续传

- 全局唯一 `sess_{uuid4}` 会话 ID
- 帧唯一标识：`sessionId + frameIndex`
- 平台重复帧直接丢弃，不写入、不报错
- 基于 checkpoint 文件实现进程重启后自动续传，不覆盖历史数据

---

### 4.2 P1 传输与数据一致性加固

**目标：** 解决带宽浪费、文件损坏、花屏、边采边播异常问题

#### 二进制传输优化

- 移除 Base64 编码，替换为 `multipart/form-data` 裸流
- 带宽降低 ≈35%，采集端 CPU 占用显著下降

#### 服务端原子写入 + 排他锁

- 帧先写入 `_staging_tmp/inflight` 临时目录
- 写入完成后原子重命名，避免半截文件
- 新增 `.locks/` 目录隔离锁：`mux.lock` / `jsonl.lock` / `parquet.lock`

#### Chunk 读写分离

- 数据块状态：`writing` → `finished`
- 前端仅加载 `finished` 完整块，避免播放跳变 / 花屏
- 通过 `info.viewer.json` 对外暴露稳定可播帧数

---

### 4.3 P2 工业级无人值守与容错自愈

**目标：** 实现 7×24h 无人值守、断网自愈、磁盘安全

#### systemd 守护进程（214 采集端）

- 用户级 systemd 服务，无需 sudo
- `Restart=always`，崩溃 5 秒后自动重启
- linger 启用，开机自动启动，无需登录

#### 断网缓存与自动重试

- 网络异常时帧存入 `_held_job` 有序重试
- 指数退避策略：0.5s → 最大 5s
- 网络恢复后按序续传，不丢已确认上传帧

#### 平台端磁盘自动化治理

- 单采集站配额：**100GB**
- 自动归档：新会话启动时归档旧会话数据
- 过期清理：保留 7 天，超配额按旧到新清理
- 磁盘水位：高水位 85%，清理目标 70%

---

### 4.4 P3 可观测性与安全加固

**目标：** 问题可追溯、传输可鉴权、内网安全

#### 全链路 sessionId 结构化日志

- 统一格式：`[datalab-stream] session=<id> frame=<n> event=<name>`
- 采集端 / 平台端使用同一 sessionId 串联全流程
- 正常帧每 30 帧打印一次，异常事件实时输出

#### 采集站 Token 鉴权

- 请求头：`X-Station-Token`
- 当前站点令牌：`dl-upload-ego-001-v1`
- 无 Token / 错误 Token 直接返回 401 拒绝
- 仅配置站点开启鉴权，兼容其他存量站点

## 7. 已知工程边界（非缺陷，硬件 / 架构限制）

### 采集帧率受限

四路 OAK 1200p 同步采集受 USB 带宽 / 硬件算力限制，实测 `capture_fps` ≈ 2–3；上传已完全异步解耦，不影响采集主线程。

### 极端断网丢帧

队列长度有限，长时间断网仍可能丢帧；checkpoint 保证已上传部分可续传，不会重复 / 覆盖。

### 鉴权范围

仅 `ego-001` 配置 Token 并强制鉴权，未配置站点不开启校验。

### 归档触发规则

仅在 **新建会话（sessionId 变更）** 时归档旧数据，同 session 续传不触发归档。
