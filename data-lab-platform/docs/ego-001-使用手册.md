# ego-001 使用手册

**130 采集 · 34 平台 · 一次录制 = 一个 episode**

| 设备 | IP | 角色 |
|------|-----|------|
| 采集站 130 | `10.10.10.130` / 手机热点 `192.168.8.1` | 录制 + 上传 |
| 平台 34 | `10.10.10.34:8080` | 派生 + 后处理 + 浏览 |

---

## 一、日常流程（最常用）

```text
1. 130 手机 UI：开始录制 → 结束录制
2. 130 终端：  ego-upload ego-001
3. 等 ~30 秒（34 自动处理）
4. 浏览器打开两个页面验收
```

### 130 上传

```bash
ego-upload ego-001
```

默认会上传 **所有 session** 里状态为 CLOSED 的待传段（一次班次录多次也只需执行一次），并通知 34 自动跑后处理。

只上传某一个 session（高级）：

```bash
ego-upload ego-001 --session-id sess_xxxxxxxx
```

仅上传、不触发 egodome 后处理：

```bash
ego-upload ego-001 --no-notify
```

### 浏览器验收

| 页面 | 地址 | 看什么 |
|------|------|--------|
| 采集质检 | http://10.10.10.34:8080/collection?station=ego-001 | 实时派生结果，按 session 列表 |
| 数据集 | http://10.10.10.34:8080/data/egodome | 后处理完成的数据集，按 episode 列表 |

**正常：** 两个页面 episode 数量一致（一次录制 = 一条）。

### 34 兜底（自动失败时）

```bash
ego-process ego-001
```

或从 34 一键（含 SSH 上传）：

```bash
ego-deliver ego-001
```

## 二、数据流（理解两个页面为何不同步）

```text
130 录制
  → segments/（本地段）
  → ego-upload
  → 34 ingest + derive-worker     → /collection 可见
  → ego-process（convert + sync） → /data/egodome 可见
```

- **Collection**：derive 完成即有（快）
- **egodome**：必须跑完 convert + Viewer 同步（慢一步）

`ego-upload` 默认会 notify 34；watcher 约 30s 内触发 `ego-process`。

## 四、常用命令

### 130

| 命令 | 作用 |
|------|------|
| `ego-upload ego-001` | 上传**全站所有 session** 待传段 + 通知 34 |
| 手机 `192.168.8.1` | 开始/停止录制、看段数 |
| `systemctl --user start ecs-record-oak-stream` | CLI 开始采集 |
| `systemctl --user stop ecs-record-oak-stream` | CLI 停止采集 |

### 34

| 命令 | 作用 |
|------|------|
| `ego-process ego-001` | derive 等待 + 后处理 + egodome 同步 |
| `ego-deliver ego-001` | 130 上传 + ego-process |
| `ego-derive status --station ego-001` | 查看派生进度 |

### 状态检查

```bash
# 34 derive 是否 READY
curl -s http://127.0.0.1:8080/lerobot/api/collection/stations/ego-001/derive-status | python3 -m json.tool

# watcher 是否在跑
systemctl --user list-timers data-lab-ego-process-watcher.timer
journalctl --user -u data-lab-ego-process-watcher.service -n 20
```

## 六、排障

| 现象 | 处理 |
|------|------|
| Collection 有、egodome 少 | 34 执行 `ego-process ego-001`；查 watcher timer |
| 130 段数很多、Collection 很少 | 确认是否跑过 `ego-upload`；新版会扫**全部 session** |
| 上传后无 notify | 查 `~/.config/ego-station.env` 中 `EGO_NOTIFY_PROCESS=1` |
| derive 卡 UPLOADED | `docker logs data-lab-derive-worker-1 --since 1h` |
| 采集启动失败 | `ego-130-verify-production.sh`；查 OAK 连接 |

## 九、MCAP Pilot（ego-mcap-pilot · Track 1）

与生产 `ego-001`（tar.zst · `:7862`）**隔离**的试点站，ingest 走 **`:7863`** pilot overlay。

### 130 采集与上传

```bash
# 首次 provision（独立 unit，不动 ecs-record-oak-stream）
bash data-lab-platform/scripts/ego-130-provision.sh --profile mcap-pilot server@10.10.10.130
bash data-lab-platform/scripts/ego-130-verify-production.sh --profile mcap-pilot server@10.10.10.130

# 130 上启动 pilot 采集
systemctl --user start ecs-record-oak-mcap-pilot.service

# 上传（固定环境变量）
export EGO_UPLOAD_URL=http://10.10.10.34:7863/lerobot/api/collection/stations/ego-mcap-pilot/upload
export EGO_SEGMENT_ROOT=/home/server/cache/ego-mcap-pilot/segments
UPLOAD_PROTOCOL=mcap STATION_UPLOAD_TOKEN=dl-upload-ego-mcap-pilot-v1 \
  ego-upload ego-mcap-pilot --notify
```

P4 端到端兜底：可用 34 上 `sess_p3_accept_golden`（golden fixture）验证 derive → ego-process；130 真机需有效 JPEG MCAP 样本。

### 34 部署与后处理

```bash
bash data-lab-platform/scripts/deploy-stream-ingest-v0.1.4-mcap.sh
ego-process ego-mcap-pilot          # derive 已 READY 时加 --skip-derive
```

`ego-process-watcher` 默认轮询 **`ego-001` + `ego-mcap-pilot`**（`EGO_PROCESS_WATCH_STATIONS`）。
